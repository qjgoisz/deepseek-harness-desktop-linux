# MCP 启动优化（2026-10-29）

本次维护包含三项：对已知服务选择单次 legacy 协商；固定本地 mcp-remote 入口，去掉启动时的 npx 查询。第三项为可选 MCP 后台初始化。没有实施按需才启动、提前显示加载窗口或其他启动策略。

## 实现及生效范围

- `patches/patch-mcp-negotiation.py` 已接入应用树构建，stdio/HTTP 均可设置 `versionNegotiation`，默认 `auto`，只允许 `auto`、`legacy`。每次重连继续使用服务配置，其他生命周期保持上游行为。未知、重复或不完整补丁拒绝写入；语法检查通过后原子替换单一模块。
- `local-fixes/mcp-startup/` 保存独立 mcp-remote 0.15.1 的 manifest/公共锁文件及显式配置工具。仅 Wolfram、OpenAlex、Exa 配置 legacy；后两者改为固定 Node 直接运行本地 proxy.js。额外命令参数、env、超时、失败策略及其他服务不变，不安装用户级 DSH 核心覆盖包。
- 配置工具在核心补丁未安装时拒绝修改配置，并校验安装的 mcp-remote 版本和目标入口。完整验证后备份并替换 YAML，保留非目标内容和 `!js` 标签。
- v2 增加 `startupMode: blocking | background`，默认 blocking，只有显式 background 且非严格服务才释放 Loader 启动屏障。后台连接完成后继续由原有真实工具注册表和通知机制提供工具、指令和资源；退出仍关闭并等待同一连接，不另建失去归属的任务。`failOnStartupError: true` 无论模式如何都保留原来的等待和失败语义。
- 配置工具为三个已知可选服务开启 background，严格服务保持 blocking；v1 核心拒绝新配置。已有前两项设置可在升级后原路重跑配置工具。只需第三步时，也可单独给相应服务设置 `startupMode: background`，无需改远端命令、协商策略或安装新的 npm 包。

具体安装、生效和回退命令见 [本地工具说明](../local-fixes/mcp-startup/README.md)。实现与验收均在独立副本进行，现用 Desktop 与配置不变；源码、测试及说明纳入本次自用分支维护提交。本机 rc.3 deb 见下文；rc.4 Desktop 更新继续暂停。正式安装仍不会因为仓库改动自动获得优化。

## 验证结果

本节前两项为较早的单次握手/本地入口验证；第三步的最新验证见下节。

rc.3 实际 MCP client / SDK 的本地进程回归确认：默认 auto 启动探测及正式进程共 2 个；legacy 只启动 1 个；工具同步和本地合成工具调用正常；重连保持 legacy，每代只一个进程；启动中取消、正常退出和严格启动失败能回收进程；无效模式在启动前拒绝。YAML 回归覆盖重复/未知配置拒绝、额外参数/env、注释、标签和幂等性。

完整离线回归 59 项：57 通过，2 项因缺少 RPM/pacman 工具跳过；构建 shell 和新增 JavaScript 语法检查通过。仅真实远端的初始化及 tools/list，没有模型请求或任务工具调用。

真实完整配置副本的 OpenAlex 使用本地 mcp-remote + legacy 成功读取 18 个工具，三轮约 9.2、6.9、10.4 秒；OCR 保持 auto 并读取 6 个工具，约 1.4–1.6 秒。这些是连接阶段时间，不能机械换算成桌面窗口提速。

**整套启动耗时尚未验收通过：**

- Exa 主动刷新失败，缓存回退后仍要求浏览器登录，未完成新一轮工具同步。未替用户登录；仅复制 OAuth 缓存至测试 HOME，未回写源缓存。此状态不能当作 legacy 连接成功，也不能当作优化带来的耗时。
- Wolfram 测试首次仍访问原用户日志路径而被只读隔离阻止；本机内核即使接收 WOLFRAM_USERBASE 环境变量和 `-userbase` 参数，查询到的 `$UserBaseDirectory` 仍是原目录。后续在测试命令内显式重设该值，不再出现相同只读日志错误，但仍未在本轮 Host 超时前完成工具同步。没有将该测试用的路径覆盖加入正式配置工具。
- 因此完整 Host 约 66–67 秒就绪包含 MCP 失败/超时，并不是所有 MCP 成功初始化的成绩；不能宣称从约一分钟降至十秒，也不能据此承诺整体提速。历史单服务探针中的 Wolfram legacy 成功记录属于此前诊断，不替代本轮验收。

当前可确认的是重复探测和启动时 npm 查询的代码路径已经改进且回归通过；Exa 当前登录状态、Wolfram 在真实安装环境下的完整初始化和最终窗口耗时仍需进一步验收。

完整 Desktop 采用独立空 HOME/DSH_HOME/XDG/user-data-dir、随机后端和调试端口，用本地假 MCP 的文件门闩控制握手，不复制用户凭据、不访问真实 MCP、不发模型请求。使用 `--no-sandbox --disable-gpu` 运行受控集成，不将这些参数加入成品。Wayland、XWayland 各通过三项（共六项）：

- 握手未完成即退出：两后端均退出码 0，约 2.1 秒关闭并回收 MCP 子进程，没有晚到工具注册。
